# Мета і задачі проекту 

Мета: створити інтерактивний веб-застосунок «Edinburgh Guide», який динамічно збирає, обробляє та візуалізує історичні дані, архітектурні пам'ятки та загальну інформацію про місто Единбург з використанням відкритих зв'язаних даних. 

# Задачі: 

Розробити серверну частину для агрегації даних із зовнішніх API. 

Сформувати семантичні запити для отримання даних про пам'ятки та історичні події. 

Реалізувати клієнтський інтерфейс для зручного відображення інформації. 

Забезпечити кешування даних на стороні сервера для оптимізації продуктивності. 

Покрити розроблений функціонал модульними тестами. 

# Перелік основних задач 

1. Отримання вступної інформації про Единбург через MediaWiki API. 

2. Написання та виконання SPARQL-запитів до Wikidata для отримання списку туристичних об'єктів та хронології історичних подій. 

3. Розробка REST API ендпоінтів для передачі даних на клієнт. 

4. Створення адаптивного користувацького інтерфейсу. 

5. Реалізація клієнтської логіки на JavaScript для асинхронного завантаження даних та управління модальними вікнами. 

Опис вхідних і вихідних даних 

Вхідні дані: 

Відповіді у форматі JSON від MediaWiki Action API, що містять текстовий опис сторінки Вікіпедії. 

Відповіді у форматі JSON  від Wikidata SPARQL Endpoint, які містять масиви об'єктів із семантичними зв'язками (назви, описи, роки заснування, посилання на зображення та сторінки Вікіпедії). 

Вихідні дані: 

Агреговані та відфільтровані JSON-структури, що генеруються бекендом для фронтенду. 

Згенерований HTML-інтерфейс, який візуалізує ці дані для кінцевого користувача у вигляді карток та списків. 

Опис ресурсів з відкритими даними 

Проект використовує два основні ресурси відкритих даних: 

Wikipedia: використовується для отримання загального текстового вступу про місто. 

Wikidata: база знань, що надає структуровані зв'язані дані. Використовується для вилучення списку пам'яток та історичних подій, відфільтрованих за географічною прив'язкою до Единбурга та відповідними типами об'єктів. 

Механізми роботи з відкритими даними 

Формування HTTP-запитів: сервер надсилає GET-запити до зовнішніх API, обов'язково вказуючи ідентифікатор клієнта User-Agent, що є вимогою політики доступу Wikipedia та Wikidata. 

SPARQL-запити: використовуються для вибірки даних з Wikidata, включаючи фільтрацію за мовою (LANG(?desc) = "en"), роками та лімітування кількості результатів. 

Декодування та обробка JSON: отримані дані десеріалізуються у внутрішні структури WikiResponse, SparqlResponse. 

Фільтрація дублікатів: під час обробки результатів SPARQL програмно відсіюються дублікати записів. 

Перелік засобів реалізації програмного забезпечення 

Бекенд: golang, використовуються стандартні бібліотеки net/http, encoding/json та net/url. 

Фронтенд: HTML5 для структури, CSS3 для стилізації, JavaScript для обробки подій. 

Тестування: 

Стандартний пакет testing та net/http/httptest у Go для написання інтеграційних та модульних тестів серверної частини. 

Фреймворк Jest \jsdom для тестування клієнтської логіки. 

Перелік засобів управління проектом 

Система контролю версій. 

Інструменти автоматизованого тестування. 

Підтримка запуску скорочених тестів. 

Головне вікно застосунку 

Головне вікно веб-застосунку має чітку логічну структуру та складається з наступних секцій: 

Header містить заголовок проекту «Edinburgh Guide» та підзаголовок, що пояснює суть сервісу. 

Секція «About Edinburgh» відображає вступний текст про місто. Якщо текст довший за 600 символів, він обрізається, і з'являється кнопка «Read more» для його повного розгортання. 

Секція «Timeline of Historic Sites» візуалізує історичні події у вигляді вертикальної хронологічної шкали з роком та описом кожної події. 

Секція «Discover Sights» представляє туристичні локації у вигляді адаптивної сітки карток. Кожна картка містить фотографію, назву та короткий опис. 

Модальне вікно з'являється при кліку на картку пам'ятки. Містить детальний опис об'єкта та кнопку для переходу на сторінку Вікіпедії або виконання пошукового запиту, якщо пряме посилання відсутнє. 

# Висновок 

Проект демонструє спосіб інтеграції Semantic Web у веб-додатки. Використання мови Go на бекенді дозволило створити швидкий шар агрегації та кешування даних із зовнішніх відкритих джерел Wikidata та Wikipedia. Клієнтська частина, реалізована на простих веб-стандартах без використання важких фреймворків, забезпечує швидкодію. Наявність модульних тестів як для бекенду, так і для фронтенду підтверджує надійність системи.
